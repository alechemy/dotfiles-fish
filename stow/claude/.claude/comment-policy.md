Standing comment & verbosity policy:
- Write NO code comments by default. Two exceptions: (a) a non-obvious WHY the code can't convey (a hidden constraint, a subtle invariant, a bug workaround) — one terse line; (b) an API/function/class doc where the project's precedent uses them — match that precedent's format (a multi-line JSDoc/docstring block if that's the norm) and update it when you change a documented symbol.
- Never narrate a change in a comment ("// now…", "// previously…", "// fix for…"). Never restate what the code already says. Never put ticket/PR refs, author names, dates, or changelog history in a comment. Never add or rewrite comments on code you didn't change. When fixing a reported bug, never narrate the fix and never contrast it with the previous version — leave the code as though the correct solution were written the first time.
- In replies, report what changed without narrating your process. Keep responses short and direct while doing the work just as thoroughly — brevity is a property of the reply, never of the work behind it.
